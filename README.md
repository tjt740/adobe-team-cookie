# Adobe Team Cookie

Adobe 母号、子号与 Cookie 管理平台，FastAPI + SQLite + 预构建 Web 界面。

## 移动端展示

沿用现有 Vue / Naive UI 组件，公共适配位于 `payload/frontend-v2/mobile-workspace.css` 和 `mobile-workspace.js`。800px 及以下使用抽屉导航；表单和按钮自动换行，宽表格在自己的区域内左右滑动，手机端不固定操作列以免遮住账号。弹窗支持内部滚动，并跟随可视区域调整高度；输入字号不小于 16px，主要按钮点击区域不小于 44px。根路径和 `/okad/` 挂载入口共用同一套适配。

移动端回归使用本地静态资源和模拟数据，覆盖 320、375、390、430、768、800px，以及 1440px 桌面宽度；检查主要管理页面（含可选监控页最多 11 页）、长文本、触屏导航、桌面折叠后切换手机、分页、表格操作、弹窗、登录和深色主题：

```bash
payload/backend/.venv/bin/python payload/frontend-v2/tests/mobile_workspace_ui.py
MOBILE_BROWSER=webkit payload/backend/.venv/bin/python payload/frontend-v2/tests/mobile_workspace_ui.py
```

运行前需在该 Python 环境安装 Playwright 及相应 Chromium / WebKit 浏览器。浏览器模拟检查之外，发布验收还应在真实 iOS / Android 设备检查系统键盘、缩放和安全区。

## 登录管理员管理

在「设置 → 管理员管理」新增管理员、编辑昵称、重置其他用户密码或启用／停用登录用户。用户名创建后不可修改，密码至少 10 个字符且不超过 72 字节。修改自己的密码仍使用「管理员密码」设置。

所有管理员共享全部账号、任务、系统设置和同一个 Sub2 连接配置，均可管理其他登录用户；此功能不提供按人隔离数据或只读角色，也不会在 Sub2 站点创建管理员。只应向可信任的同事开放。普通历史登录用户不能使用登录用户管理接口。

「okad 管理平台」标题旁的眼睛按钮可展开本地和线上登录凭据，默认收起，只有点击时才读取密码。线上可在私有配置中显式启用 `public_on_online`，启用后生产域名的登录页只返回线上条目；未启用时仍仅允许已登录的管理员查看。本地显式启用回环访问后，登录页也可查看。凭据登记保存在私有的 `.local/login-hints.json`（容器为 `/app/data/.local/login-hints.json`），不进入前端资源或 Git。收起、跳转或切到后台时清除显示内容；通过「管理员密码」修改当前环境的密码后同步更新已登记提示。

不能停用当前登录账号，始终保留至少一个启用的管理员。停用或重置密码使该用户旧登录会话立即失效，重新启用也不会恢复旧令牌；已提交的后台任务继续运行。用户管理操作记录到系统日志，不记录密码。升级保留现有账号和密码，不自动创建额外登录用户。

## 号池账号获取 Cookie 并推送 Sub2

管理页面采用统一的统计、筛选、批量操作和列表分区。母号的清退与同步号池操作收在「更多批量操作」；外部子号的导入表单、Sub2 连接配置及号池推送明细默认展开，可手动收起；邮箱凭据通过「查看 / 编辑」查看；设置顶部可按类别定位。

「外部子号」和「Sub2 管理」分别使用 `/external-members` 和 `/sub2` 独立路由。所有菜单的文字、图标和空白区域均可跳转；刷新、打开书签或浏览器前进后退时，内容、标题和菜单选中项保持一致。旧版 `panel` 参数链接自动跳转到对应路由。从号池导入说明进入 Sub2 配置后，关闭配置可返回号池并恢复勾选。

「任务列表」使用摘要卡片，支持按编号、邮箱、操作者、来源和状态筛选。点击「查看详情」可查看账号结果、执行记录、发起入口、操作者、筛选条件及关联的重试任务。新任务在发起时保存账号邮箱和来源快照，账号改名或服务重启后仍可追溯；旧任务缺失的信息显示「未记录」，不会用当前账号数据冒充历史。执行中可按任务支持情况暂停、继续或终止；历史任务仍可删除，号池登录任务可重试未完成账号。

号池默认显示全部类型。批量删除母号时，仅移除它在号池中的记录，后续刷新不再自动生成，母号管理中的账号仍保留；删除完成后会同步刷新列表和统计数量。

在「Sub2 管理」保存地址、管理员密钥、Adobe Firefly 平台及 Adobe 分组。回到「号池管理」，勾选子号或导入账号，点击「导入 Sub2」。缺少 Cookie 时使用号池自身的邮箱取信配置登录 Adobe，Cookie 直接保存在原号池记录；已有 Cookie 时直接使用。该流程不创建或使用外部子号记录。

「导入 Sub2」旁的问号可查看前置条件并跳转配置。未保存管理员密钥等必要配置时，按钮不可用；保存后自动更新。导出格式收在顶部「导出」菜单，单个账号的测试、刷新操作收在「更多」菜单，推送任务完成后保持明细的展开或手动收起状态。

只有已登录、Cookie/Token 齐全且积分达到 4000 的账号会推送。已有 Sub2 库存的账号跳过，推送完成后自动刷新库存标签。页面显示逐账号进度和失败原因，刷新页面后可继续查看任务，也可从任务列表查看历史。推送失败保留 Cookie，重新勾选即可重试；服务重启中断的任务需手动重试，重试前会检查远端库存。原有 FF-iOS Token 与设备凭据保留。此按钮用于新号入库，不会自动更新已有 Sub2 账号的 Cookie；在库不代表已验证出图。

## 外部子号推送到 Sub2

外部子号支持每行只填邮箱批量导入；自动取码时按粘贴顺序逐个获取验证码并登录，不受全局并发设置影响。同批重复邮箱只登录一次，单个账号失败后继续下一个，可在账号行查看各自进度和结果。后续重登也固定走验证码（即使此前保存过密码或登录补全时生成了密码）。选择自动取码时，先在邮件配置中保存 supply.ink Token；账号需在该 Token 可查询的账号库中。自动模式缺少取信配置时会直接提示，不会发送验证码；普通账号可改用下述手动验证码模式。已有账号需选择「覆盖」才能通过导入切换方式，覆盖保留 Cookie、备注、邮箱凭据和 Sub2 关联。

也支持 `邮箱----Adobe密码`（以及 `邮箱|Adobe密码` 或制表符），先尝试密码登录；Adobe 要求邮箱二次验证或密码认证未通过时，自动获取验证码。覆盖导入带密码的格式会恢复密码优先。原有四段／五段及取信 URL 格式继续有效。

仅有账号密码且选择自动取码的邮箱，在导入区将「取码方式」选为「自动取码（supply.ink）」，才会显示「邮件配置 · supply.ink」折叠框。选择手动输入或保留设置时隐藏配置框，不清除已保存的 Token。在配置框保存邮件助手的 Token 裸串，并点击「测试连接」。账号必须属于该 Token 可查询的 supply.ink 账号库；有完整邮箱凭据或取信 URL 的账号继续使用原取信方式。邮件 Token 保存在项目数据库，管理员可替换或清除，接口不回显明文。行内「邮件」可查看最近五封邮件和纯文本正文；自动登录只接受新收到的 Adobe 验证码，跳过旧邮件、收件人不匹配及本次登录已用过的验证码。supply 返回无时区的邮件日期时按中国标准时间解释。

页面导入、选中重登和一键重登按每批最多 50 个账号执行，上一批结束后再开始下一批；批内并发沿用设置并限制在 50 以内，仅邮箱自动取码仍按顺序逐个处理。单个账号登录成功后立即提交 Sub2 推送，使用任务提交时登记的目标地址；失败账号记录原因后继续。Sub2 推送失败保留已保存的 Cookie，可单独点击「推送 Sub2」重试，不必重新登录。

通过 supply.ink 获取验证码的账号，邮箱旁显示绿色「公司」标签与标签图标。标记按账号的取信方式显示；已有完整 ClientID/RefreshToken 或取信 URL 的账号不显示此标签。

普通账号无需接入 supply.ink：导入区的「取码方式」选择「手动输入验证码」，每行填邮箱或 `邮箱----Adobe密码`。仅邮箱直接发码；带 Adobe 密码先尝试密码登录，只有需要验证时才等待手动输入。账号行出现「填验证码」后，从自己的邮箱查看 Adobe 邮件，在弹窗填写 6 位数字并提交；登录继续获取 Cookie、积分，之后照常推送 Sub2。已有账号可在邮箱下方切换「自动取码 / 手动验证码」，下次登录生效；任务未结束时不能切换。覆盖导入未指定取码方式时保留原选择。

手动模式不调用 supply.ink，也不显示「公司」标签。每次验证码请求有独立的有效期（默认 180 秒），并发账号分别提交；若登录再次要求验证码，会出现新请求，旧窗口不能提交给新请求。关闭窗口可在有效期内重新打开；验证码被 Adobe 拒绝时，按页面的新请求填写最新邮件中的验证码。登录任务失败或服务重启后需重新登录。任务终止会结束等待，失败保留已有 Cookie。验证码只在进程内短暂交接，不落库、不进入日志；刷新页面可重新打开尚未到期的请求。该交接适用于项目默认的单进程服务。

外部子号列表在「最后登录」后依次显示「最后推送cookie 时间」「备注」「操作人」。推送时间显示最近一次成功写入当前 Sub2 的时间，精确到秒；手动推送、登录后推送及 Sub2 检测 Cookie 失效后的自动刷新重推都会更新，未成功推送过显示「—」，失败保留上次成功时间。点击账号操作区的「备注」可填写或修改，支持多行文字，最多 1000 字；清空后保存即可删除备注。备注保存在账号记录中，重登和覆盖导入保留原有备注。

外部子号列表默认每页 200 条，可选择 50、100、200 条，支持首页、上一页、下一页、末页及输入页码跳转。修改筛选条件或每页条数时返回第一页；翻页时清空勾选，全选仅选择当前页。自动刷新保留当前页，删除后若当前页已不存在则返回最后一页。「一键重登全部」与未勾选时的导出仍覆盖全部匹配账号。

「登录配置」是可选功能，默认不指定，沿用原来的自动选择逻辑。勾选一个或多个账号后，在「选中批量重登」旁的「批量登录配置」选择个人配置或组织配置优先，选择后统一保存到勾选的账号，下次登录生效，也可随时改回「不指定（原逻辑）」。所选账号设置不同时显示「所选配置不一致」；「当前配置」仍显示最近一次登录的实际结果。单号重登、选中批量重登和一键重登都按各账号保存的选择执行，任务提交时记录本次选择。行内和导入区不提供配置选择；新导入账号默认不指定，覆盖导入已有账号时保留原设置。所选账号中有登录任务未结束时不能修改选择。

选择个人配置时直接使用个人身份，不会自动切到组织。「组织配置优先」会使用未停用且没有删除标记的组织配置；名称带 `DEL-` 前缀、`Deleted` 或“已删”的组织会跳过，全部跳过时使用个人配置。选中的组织若被 Adobe 明确判定为授权过期（状态原因 `2000`），会重新建立个人配置会话，再查询积分。积分为零或授权查询暂时失败不会触发切换。账号详情保留所有已获取配置，并标注疑似删除或授权过期的配置；个人配置的额度以实际查询为准。切换后会核对 Token 身份，避免保存与积分身份不一致的会话。

「外部子号」的「一键重登全部」和「重新关联 / 推送」默认收在「更多操作」中。设置筛选条件后，「一键重登全部」变为「一键重登筛选结果」，覆盖全部匹配账号（不受列表显示条数限制），自动跳过任务未结束的账号。也可直接勾选账号后点击「选中批量重登」。点击邮箱会复制账号邮箱，左侧箭头可展开任务进度和日志。

在「Sub2 管理」配置地址、管理员密钥、Adobe Firefly 平台和 Adobe 分组，测试连接成功后，在「外部子号」勾选登录成功且有 Cookie 的账号，点击「推送 Sub2」。同步在后台执行，账号行显示待同步、同步中或失败原因；成功时间显示在「最后推送cookie 时间」列并随页面自动刷新。登录状态不重复显示「登录成功；已提交 Sub2 推送，可查看账号同步状态」。失败可再次点击推送重试。

账号行的 Sub2 标签旁提供「详情」，用「登录信息」「网络线路」等日常说法说明当前情况和下一步操作，展示 Sub2 账号编号、系统提示和最近记录时间。Cookie 已写入但等待代理就绪时，显示「已发送到 Sub2，正在等可用线路」，说明无需重新登录或重复推送，请管理员检查线路和空位；尚未发送、等待检查及发送失败分别说明。详情随列表更新，桌面和手机均可点击查看；打开详情只读取状态，不触发登录、推送或检测。

等待线路的详情会额外只读核对 Sub2 的账号与节点容量。确认账号尚未分配线路、自动分配已开启、没有空位且账号总数超过全部节点容量后，弹窗盖上 Canvas 红色印章「账号已经超出节点容量限制，老铁。」，并显示实际数量。每 30 秒重新核对，状态变化或核对失败时隐藏；单纯线路故障、信息缺失或未超限不盖章。印章不拦截点击，也不触发登录、推送、代理探测或配置修改。

手动「推送 Sub2」或「重新关联 / 推送」时，所选账号只要有掉订阅、积分查询失败或订阅状态未知的情况，就会列出异常邮箱和原因，要求管理员点击「确认推送」。取消或关闭弹窗不会提交推送，勾选保持不变；混合选择会明确提示本次推送的总数。全部订阅正常时，普通推送直接执行。此提醒仅用于这两个手动入口。

外部子号页面可见时，每 3 秒按完整邮箱核对当前 Sub2 库存。从号池或其他入口导入的同邮箱账号也会显示「在库 Sub2」；远端删除后会变为「未在库 Sub2」，连接异常则显示「Sub2 状态暂不可用」。点击「刷新」可立即核对。库存核对仅查询状态，不会重复推送、覆盖 Cookie 或自动开启外部子号重登同步。

首次推送会创建或按邮箱关联同一个远端 Adobe OAuth 账号。之后该外部子号每次登录成功，都会更新关联账号的 Cookie 并清除旧 Token 缓存，保留远端分组、代理及其他设置。本地登录结果与同步结果分别记录；同步成功表示 Cookie 已写入，不代表已验证出图。

对外的 `/api/v1/adobe/cookie/refresh` 被 Sub2 用于处理 Cookie 失效时，会复用同一套外部子号登录流程。登录成功后，系统会按邮箱查找现有的 Sub2 Adobe 账号并异步写入新 Cookie，即使本地还没有保存关联编号；找不到远端账号时只记录同步失败，不会借此请求自动创建新账号。

关联按 Sub2 地址隔离。登录任务执行期间更换地址会停止该任务向新地址推送，可手动推送或重新发起登录；删除远端已关联账号后会提示失败，不会自动重建。本地删除外部子号不会删除远端账号。页面发起的新登录任务可以推送此前未关联的账号；对外 Cookie 刷新接口仍只更新已存在的同邮箱账号。此功能独立于「号池管理」的巡航自动推送开关。

账号行分别显示排队、登录、本轮成功、失败和中断状态。服务重启后，未结束的登录任务自动标记中断，保留已完成结果、Cookie 和日志，不自动重放登录请求；可重新勾选未完成账号执行。

「登录成功」表示已取得 Cookie；积分查询结果单独显示在「订阅」列。查询失败时显示橙色单行标签「积分查询失败」，悬停可查看 HTTP 状态码和可识别的 Adobe 错误码，点击可查看原因及重试说明。尚未查询的账号显示「待查询」；历史记录缺少积分且未保存原因时显示「积分未查到」，悬停及详情提示订阅状态未知，不会据此判定掉订阅。重新登录会重新查询，成功后清除错误提示；页面「刷新」只读取已保存的结果。错误提示不保存接口响应正文或凭证。

远端关联账号已删除并返回 404 时，勾选账号后点击「更多操作 → 重新关联 / 推送」并确认：先按完整邮箱查找现有 Adobe OAuth 账号，找到则更新关联和 Cookie；确实不存在时，按当前 Sub2 分组配置创建新账号。此操作可能恢复其他管理员已删除的账号。重复邮箱、身份不一致、鉴权失败或无法完整查询库存时停止操作。恢复保留本地账号和登录历史，并记录旧编号及操作者；普通推送和自动重登同步不会自动重建已删除的关联账号。

## 列表分页

各账号列表、母号成员、任务及任务详情、系统日志、Sub2、管理员和联动中心统一支持每页 100、200、300、400、500、1000 条，并保留 50 条。通过「自定义」输入 1–10000 的整数后点击「应用」；切换每页条数会回到第一页。任务中心可继续「加载更早任务」后分页查看历史任务。

外部子号支持 Sub2 在库状态及导入日期范围组合筛选；结束日期包含当天，日期按浏览器本地时区换算。分页总数、导出和筛选批量重登使用相同条件。
