## 号池账号获取 Cookie 并推送 Sub2

管理页面采用统一的统计、筛选、批量操作和列表分区。母号的清退与同步号池操作收在「更多批量操作」；外部子号的导入表单、Sub2 连接配置及号池推送明细默认展开，可手动收起；邮箱凭据通过「查看 / 编辑」查看；设置顶部可按类别定位。

「外部子号」和「Sub2 管理」的菜单选择保存在地址栏的 `panel` 参数中，刷新、打开书签或浏览器前进后退时，内容、标题和菜单选中项保持一致。关闭 Sub2 配置后返回原页面，并保留号池的勾选状态。

「任务列表」使用摘要卡片，支持按编号、邮箱、操作者、来源和状态筛选。点击「查看详情」可查看账号结果、执行记录、发起入口、操作者、筛选条件及关联的重试任务。新任务在发起时保存账号邮箱和来源快照，账号改名或服务重启后仍可追溯；旧任务缺失的信息显示「未记录」，不会用当前账号数据冒充历史。执行中可按任务支持情况暂停、继续或终止；历史任务仍可删除，号池登录任务可重试未完成账号。

号池默认显示全部类型。批量删除母号时，仅移除它在号池中的记录，后续刷新不再自动生成，母号管理中的账号仍保留；删除完成后会同步刷新列表和统计数量。

在「Sub2 管理」保存地址、管理员密钥、Adobe Firefly 平台及 Adobe 分组。回到「号池管理」，勾选子号或导入账号，点击「导入 Sub2」。缺少 Cookie 时使用号池自身的邮箱取信配置登录 Adobe，Cookie 直接保存在原号池记录；已有 Cookie 时直接使用。该流程不创建或使用外部子号记录。

「导入 Sub2」旁的问号可查看前置条件并跳转配置。未保存管理员密钥等必要配置时，按钮不可用；保存后自动更新。导出格式收在顶部「导出」菜单，单个账号的测试、刷新操作收在「更多」菜单，推送任务完成后保持明细的展开或手动收起状态。

只有已登录、Cookie/Token 齐全且积分达到 4000 的账号会推送。已有 Sub2 库存的账号跳过，推送完成后自动刷新库存标签。页面显示逐账号进度和失败原因，刷新页面后可继续查看任务，也可从任务列表查看历史。推送失败保留 Cookie，重新勾选即可重试；服务重启中断的任务需手动重试，重试前会检查远端库存。原有 FF-iOS Token 与设备凭据保留。此按钮用于新号入库，不会自动更新已有 Sub2 账号的 Cookie；在库不代表已验证出图。

## 外部子号推送到 Sub2

在「Sub2 管理」配置地址、管理员密钥、Adobe Firefly 平台和 Adobe 分组，测试连接成功后，在「外部子号」勾选登录成功且有 Cookie 的账号，点击「推送 Sub2」。同步在后台执行，账号行显示待同步、同步中或失败原因；同步成功的时间可在库存标签提示中查看。失败可再次点击推送重试。

外部子号页面可见时，每 3 秒按完整邮箱核对当前 Sub2 库存。从号池或其他入口导入的同邮箱账号也会显示「在库 Sub2」；远端删除后会变为「未在库 Sub2」，连接异常则显示「Sub2 状态暂不可用」。点击「刷新」可立即核对。库存核对仅查询状态，不会重复推送、覆盖 Cookie 或自动开启外部子号重登同步。

首次推送会创建或按邮箱关联同一个远端 Adobe OAuth 账号。之后该外部子号每次登录成功，都会更新关联账号的 Cookie 并清除旧 Token 缓存，保留远端分组、代理及其他设置。本地登录结果与同步结果分别记录；同步成功表示 Cookie 已写入，不代表已验证出图。

关联按 Sub2 地址隔离。更换地址后需要重新手动推送；删除远端已关联账号后会提示失败，不会自动重建。本地删除外部子号不会删除远端账号。此功能独立于「号池管理」的巡航自动推送开关，尚未手动推送过的外部子号不会自动上传。

docker compose ps
