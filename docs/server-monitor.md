# 服务器监控

在管理后台侧栏点击「服务器监控」。根路径部署入口 `/server-monitor`，同机挂载入口 `/okad/server-monitor`。使用现有管理员登录，无需另建监控账号。

## 数据与判断

| 指标 | 范围与含义 |
| --- | --- |
| 整机 CPU / 内存 | Linux `/proc` 可见的主机计数。CPU 取两次采样的差值；内存为 MemTotal − MemAvailable。 |
| 应用 CPU / 内存 | 当前 cgroup，Docker 部署中即应用容器，包含其子进程。CPU 相对可见配额和 CPU 亲和性的较小值；内存包含缓存，按可见上限计算。 |
| 数据盘 | SQLite 数据库所在文件系统的容量、已用和可用空间，并非数据库文件大小，也不包含所有磁盘。 |
| 网络 | 当前网络命名空间内非 loopback 网卡的收发字节差值；普通 Docker 网络下为当前容器流量。 |
| 请求 | 此 Okad 进程的 API，请求完成后累计，排除监控和健康检查。60 秒窗口显示吞吐、平均/P95 耗时、4xx 和 5xx，另显示当前处理中请求数。 |
| 后台任务 | 当前进程任务管理器内的运行、暂停和停止状态；不包含联动恢复的独立队列，任务数不等于账号并发数。 |
| OOM 终止 | cgroup v2 memory.events 的 oom_kill 累计，按资源组生命周期计数；不代表当前仍发生 OOM。 |

资源使用率 80% 提醒、90% 标红；同时关注趋势和请求耗时。5xx 非零也会提醒。没有请求时 P95 和错误比例显示 `—`。未设置可见内存上限时，应用内存卡仅展示字节用量。

第一条 CPU、网络采样需要等待下一轮计数。采样缺失、网络计数重置或接口变化都显示空缺，避免产生虚假的零值或尖峰。非 Linux 本地开发环境的部分资源数据不可用。

## 运行与开销

- 应用启动时启用后台线程，每 5 秒采样，最多保留 721 个采样点（约 1 小时）；不依赖浏览器打开，不写数据库，重启后重新积累。
- HTTP 计数为 60 秒窗口，按整秒聚合；P95 最多使用最近 10,000 条耗时样本。统计与任务摘要均不保存 URL 参数、请求内容、邮箱、Cookie 或 Token。
- `GET /api/monitor/snapshot?minutes=15` 使用现有登录鉴权；范围 1～60 分钟，返回缓存采样，设置 `Cache-Control: no-store`。
- 页面每 5 秒刷新，离开页面或切换到后台标签页时停止轮询；请求超时或采样超过 15 秒未更新时提示数据过期。支持暂停刷新、时间范围切换。
- 默认单进程部署。多 worker 会各自维护历史、请求和任务统计；不能据此当作整个集群的聚合值。
- 无新增依赖，不需要挂载 Docker socket 或授予特权。不主动访问外部服务，不执行登录、推送或压力测试。

采集语义参考 [Linux /proc 文档](https://docs.kernel.org/filesystems/proc.html) 与 [cgroup v2 文档](https://docs.kernel.org/admin-guide/cgroup-v2.html)。不可见的上层配额及虚拟化后的主机计数受运行环境限制。

## 验证

后端测试：`cd payload/backend && .venv/bin/python -m pytest tests/test_server_monitor.py -q`。

浏览器验证：`payload/backend/.venv/bin/python payload/frontend-v2/tests/server_monitor_ui.py`，使用模拟数据，覆盖根路径与 `/okad` 挂载、趋势、暂停/恢复、网络错误、缺失值、导航、刷新和窄屏布局。
