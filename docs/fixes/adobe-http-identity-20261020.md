# Adobe 会话校验修正（2026-10-20）

本次确认并修正两个缺陷：

- 生产 curl_cffi 0.7.4 使用 Chrome 124 TLS，而登录头随机声明 Chrome 131/136。请求头现从实际 TLS 配置生成；初始化失败不再静默更换传输。
- IMS 发出 token 后，业务额度接口可能立即返回 HTTP 401 / 401013。此前仍返回“登录成功”，覆盖源 Cookie 并进入推送。现在遇到明确 401 立即停止，不重试已失效凭据，不触发补资料或密码变更，沿用失败路径保留原凭据。403、限流、网络失败和未知额度保持原语义，不能误当作登录失效。

## 已验证的范围

新增回归覆盖浏览器版本一致性、401 不被后续超时掩盖、IMS 成功而业务认证失败时拒绝保存、403/超时仍可返回有效认证资料。Python 3.11 下后端全量 679 项测试通过，另有 3 项既有依赖弃用警告。

线上只对用户指定的两个账号做受控测试。主号仅修正登录头后曾出图成功，但约 15 分钟后再次被 Adobe 拒绝。因此请求头修正本身不能证明已经解决主号 401。备用号在独立进程、相同出口和 Chrome 124 请求环境下连续 6 次出图成功；42 分钟后原始 token 仍能查询实时额度，但 Cookie 换 token 返回 invalid_credentials。该观察也不能替代业务流量下的持续验证。

在相同平台代理重新获取主号会话时，额度接口直接返回 401，旧实现却保存为登录成功，复现了本次校验缺陷。该补丁会拒绝这种结果。

尚未证明会话短时失效的唯一原因，也未证明已恢复两号长期可用。登录与业务出口绑定、令牌复用、官网完整会话与平台生成链路的差异仍待对照。实验代理代码已移出发布变更，未改生产网络、代理分配、并发配置或其他账号。

## 发布与回退

`deploy/primary/http-identity-release.py` 只覆盖 HTTP 客户端和 Firefly 会话校验两个文件，复用发布锁、运行时完整源码哈希、配置和账号身份检查、空闲条件、SQLite 备份及代码回退保护。保留当前运行镜像中其他叠加内容，发布前重新核对容器、镜像和文件哈希。

在同一发布目录执行 `check-rollback` 可只读核对回退条件；执行 `rollback` 时仍需没有后续版本和配置变化且登录作业空闲。回退只恢复代码，不恢复旧业务数据库。
